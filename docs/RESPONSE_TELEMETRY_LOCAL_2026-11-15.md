# Локальная телеметрия ответов, 15 ноября 2026

Цель этапа: видеть отправку, ожидание, проверку и сохранение ответа, чтобы следующие исправления опирались на фактические данные. Решения агента о товарах и источниках не изменены. Подготовлен локальный патч; публикации и проверки живого виджета в этом этапе нет.

Существующий журнал не показывал все наблюдаемые расходы при ошибках проверки ответа. Отметки отдельных запросов было трудно связать с response ID. Метрика показа ответа отбрасывала значения свыше десяти минут. Эти пробелы исправлены через существующий механизм diagnostics, без второго журнала.

## Проверки

Финальный общий прогон: **2021 passed, 1 skipped**, 149 тестовых файлов прошли. Пропущена интеграционная проверка с PostgreSQL. `npm run typecheck`, `npm run build`, `npm run lint:no-regex` и `git diff --check` прошли.

Новые тесты проверяют успешное завершение, восстановление чтения того же ID без повторного POST, неизвестный исход POST без повторной отправки, локальную и провайдерскую отмену, failed/incomplete, ошибку проверки содержимого, отказ checkpoint и отказ приёмника диагностики. Приватные строки в запросе, ответе, карточках, источниках и ошибках не попадают в события. Повторные наблюдения сохраняют usage как снимок, а не новый расход.

Локальная проверка сохранённого диалога сравнила целиком три подготовленных плана с зафиксированными v2-планами. Совпадают запросы, schema, manifest, контрольные суммы и контекст. После чтения сохранённого ответа совпадает всё итоговое состояние: **132 оценки и 34 выбранные модели**. Token counting и чтение ответа в этой проверке полностью подменены локальным транспортом; отправок модели нет.

Проверка SHA-256 подтвердила неизменность **76 защищённых файлов**, включая ZIP `catalog-review-stable-011e9e0cd5a347059952e1b28fa357d4.zip`. Код `prepare`, SQL checkpoint, денежный guard и существующий журнал также проверены на неизменность. Предыдущие benchmark-файлы не перезаписаны.

## Значение и границы измерений

- `providerCompletedAtMs` содержит только реально полученный числовой `completed_at`. Когда поля нет или оно невалидно, значение строго `null`. Время создания response не используется вместо времени завершения.
- `observedAtMs` означает время нашего наблюдения. Интервал отправка–наблюдение включает сеть, опрос и ожидание; это не время вычисления модели.
- `firstObservedTerminal` действует в пределах одного execution. При восстановлении тот же ID может снова иметь `true`. Для объединения executions нужно брать самое раннее доступное наблюдение по ID, учитывая полноту журнала.
- Usage является повторяемым снимком `usage_snapshot_not_delta`. Повторные снимки нельзя складывать как отдельные расходы. Денежный ledger не изменён. Неизвестный usage не превращается в ноль.
- Неизвестный POST, нечитабельное тело, отсутствующий ID и отсутствующий usage нельзя восстановить одной телеметрией. Тела HTTP-ошибок не добавлены в диагностику. Подтверждение session API означает HTTP acknowledgement, а не завершение модели.
- Существующие ограничения сохранены: до 20000 обычных событий на execution, ограниченная очередь 5000 плюс резерв 100, retention по умолчанию 7 дней с настройкой 1–30. При потерях событий выводы ограничены существующими счётчиками полноты. Новое множество терминальных ID ограничено 20000 и живёт только в execution.
- UI-метрика показывает возможность отрисовки после двух animation frames. Она не доказывает прочтение покупателем; вкладка и доставка метрики могут прерваться. Фактический виджет здесь не проверялся.

## Отклонение первого тестового прогона

Один новый тест ошибочно передал mock transport третьим аргументом PlatformAgentClient вместо четвёртого. Он попытался обратиться к внешнему API с фиктивным ключом и получил **401**. Успешного вызова модели не было. Ошибка исправлена; новые тесты теперь запрещают глобальный fetch и передают транспорт явно. Поэтому весь этап нельзя описывать как полностью лишённый сетевых попыток. Остальные найденные ошибки тестов и их исправления записаны в `problems.md`.

PostgreSQL, установки зависимостей, push, PR, deploy, публикация и изменение каталога не выполнялись. Независимое ревью текущего патча ещё не проведено. Скорость, кэширование, полнота production-журнала и качество ответов этим этапом не доказаны.

## Следующая проверка

1. Независимо проверить `telemetry-only.patch` и приложенные исходные артефакты. Проверить сохранность бизнес-исходов и отсутствие приватного текста в новых событиях.
2. В отдельном этапе публикации проверить журнал и recovery в PostgreSQL. При повторном чтении одного ID не должно появляться второй денежной записи.
3. После публикации провести диалог через виджет `https://bakautprof.ru/`, читая каждый ответ перед следующей репликой. Сопоставить отправку, response IDs, usage, проверку, сохранение и UI-метрику. Отсутствующий `completed_at` должен остаться `null`.
4. По этим данным отделить задержки провайдера от ожидания опроса, проверки и записи. Решение об оптимизации принимать после этого сопоставления. Отдельно оценивать полезность предварительного вывода бота и самостоятельность выбора источников.
