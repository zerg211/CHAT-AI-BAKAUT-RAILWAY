# Изменения менеджера и знаний v18

Основание: пользовательский план `BAKAUT_AI_AUDIT_AND_PLAN_2026-09-07.md` и финальный комплект `BAKAUT_TESTS_V2`. Подключение склада, расчёта доставки, резерва и статусов заказа исключено пользователем.

## Поведение и граница модели/кода

1. Планировщик по-прежнему определяет намерение, смену требований, ссылки на предыдущие товары и необходимые характеристики. Короткий путь не распознаёт фразы покупателя: он проверяет структурированные `grounding.taskType`, `responseMode`, `technicalAttributes`, `sourcePolicy` и фактическую полноту каждого товара. При полном наборе данных пропускается повторный observer; writer и фактические проверки сохраняются. Явный запрос web, уточнение или конфликт отключают этот путь.
2. Техническая точность, бюджет и разрешение на заявку остаются блокирующими условиями. Замечание о рассказе процесса исследования допускает ограниченную перепись, но не уничтожает уже прошедший фактическую проверку оригинал. Неудачная проверка нового черновика не переносится на другой текст. Недоступность самой проверки фактов остаётся блокирующей.
3. У writer и repair выделен резерв на последующую проверку. Буквально повторённые блоки политики удалены. Ошибка инфраструктуры больше не предлагает покупателю сократить понятный вопрос.
4. Известный точный товар не запускает повторный общий поиск ради той же найденной модели. Механические проверки идентичности сохраняют суффиксы; смысл допустимых альтернатив остаётся в планировщике. Остальные старые keyword/classifier эвристики не объявляются полностью переписанными.

## Знания и данные

- Миграция 029 разделяет identity/technical/commercial версии. Исторический полный source hash остаётся для происхождения данных. Цена, картинка и служебный raw не сбрасывают техническую память. Имя, модификация, технические характеристики или описание меняют technical version; legacy-факты привязываются только при совпадении актуального прежнего hash.
- Канонические физические единицы сравниваются только при распознаваемом целом значении. Условия, диапазоны, kW/kVA, номинальная/максимальная мощность и модификации не склеиваются по похожему числу. Старые исходные attribute/value/evidence остаются доступными; чтение не требует массового переписывания старых записей.
- Поиск памяти получает запрошенные слоты и лимит на товар, а не один общий `slice(0,32)`. Нужная масса не вытесняется 40 более новыми посторонними фактами.
- Миграция 030 добавляет устойчивую очередь фактов. В неё попадают только прошедшие существующую проверку точного источника сведения, с датой наблюдения и версией модели. Worker нормализует и публикует их с idempotency, lease fencing и ограничением повторов. Поздний старый источник не подменяет более свежий; изменённая модификация не получает прежний queued-факт. Повторное использование не обновляет дату верификации.
- Основной источник чтения — `verified_product_facts`; старое зеркалирование `product_facts` не является условием доступности новой памяти. Очередь и её ошибки доступны в `/api/admin/health`.

## Конфигурация и измерение

Модели ролей берутся из явных переменных; default — Luna. Действующие production-переменные проверены перед обновлением: answer/planner/fact — `gpt-5.6-luna`. Ограниченные production effort defaults сохранены; сравнительный эксперимент с другими моделями здесь не объявляется проведённым.

В metadata сохраняются реально выбранные модели, размеры входного контекста/JSON schema по стадиям и бюджет. `first_useful_content_emitted` означает отправку сервером сохранённого и принятого ответа; не статус SSE и не момент отрисовки браузером. Браузерное ожидание оценивается отдельно в live-протоколе. `estimatedCostUsd` — резерв/оценка, не фактический счёт провайдера.
