# V4: эксплуатация и проверка целостности

Источник требований: BAKAUT-PLAN-V4-2026-09-11. Этот документ описывает реализацию и бесплатные проверки; он не заменяет приёмку настоящей модели и виджета.

## Владельцы данных

| Данные | Все пути записи | Чтение и гарантия |
|---|---|---|
| Цена | crawler, sitemap, CSV через `upsertProduct`; `updateVerifiedSitePrice` | PostgreSQL trigger согласует цену, валюту, наблюдение, доказательство и `product_facts`. Отсутствие цены не удаляет известную цену. «По запросу» требует датированного наблюдения. |
| Технические данные товара | `upsertProduct`, backfill embeddings | Изменение technicalVersion инвалидирует производные; запоздалый backfill отклоняется по версии. |
| Страницы компании | sitemap; `site.readFirstPartyPage` → durable job → knowledge worker | Полный публичный текст хранится отдельно от excerpt. Старое наблюдение не заменяет новое; вектор страницы пригоден только для её текущей source revision. |
| Проверенные факты | direct upsert; enrichment queue; ручная курация status | Общая транзакционная блокировка субъекта, fencing lease, item outcomes, quality replacement. Отзыв источника блокирует его повторную публикацию, сохраняя независимые источники. |
| Заявки | разрешённый `lead.capture`; форма → lead + outbox | Имя необязательно. Вопрос и выбранный способ связи сохраняются. Подтверждение действия только после durable capture; HTTP-письмо идемпотентно и отделено от UI. |
| Сессии | turn owner, heartbeat, maintenance | Активные принятые ходы, сообщения и заявки не удаляются очисткой пустых сессий. |

LLM определяет намерение, роль числа, смену требований, допустимость альтернатив и необходимость исследования. Код проверяет identity, источники, числа, обязательные конфликты, полномочия и согласованность действия. Неизвестное свойство не означает несовместимость. Прямой запрос человека не требует фиктивного предварительного исследования; авторизация контакта проверяется независимо.

Калькулятор принимает отдельно рабочую и пусковую полную мощность в кВА с подтверждённым коэффициентом мощности каждого режима. Пересчёт в кВт сохраняет исходные наблюдения; неизвестный PF или конфликт исходных чисел не даёт подтверждённого минимума. Пересчёт памяти сохраняет все потребители и одновременность работы. Этот расчёт активной мощности сам по себе не подтверждает допустимые кВА генератора, токи по фазам или гарантированный пуск.

При отмене проверки цены новые чтения и запись результата не начинаются. Общий запрос может закончиться для другого ожидающего покупателя. Неизвестный исход вызова OpenAI сохраняет суточный резерв; отсутствие usage не считается нулевым расходом.

## Совместимость

Миграции 039–043 добавляются после существующих миграций. 039 вводит связь вектора страницы с source revision; старые векторы с неизвестной связью не используются. 040 сохраняет outcomes каждого элемента в существующей очереди. 041 вводит согласованную цену для всех writers. 042 добавляет наблюдение страницы и публикацию company page в существующей очереди. 043 разрешает NULL имени в заявке.

Старые фактовые jobs с facts[] продолжают читаться; page_payload необязателен. Новые поля наблюдения/range добавлены к результатам tools; старые сохранённые результаты не превращаются в новые побочные действия. Внешний API формы совместим со старым обязательным именем. После обновления клиент должен загрузить новый asset из текущего index.html.

## Бесплатный preflight и ремонт старых данных

`node --import tsx src/scripts/knowledgeInventory.ts` выполняет только READ ONLY transaction и выдаёт агрегаты, миграции и несекретную конфигурацию. Команда не выводит контакты, тексты заявок, ключи или URL подключения. `ECONNREFUSED` означает недоступную БД, а не пустой каталог.

`npm run embeddings:backfill -- --dry-run --limit=100` только планирует работу. `--content-only` и `--products-only` ограничивают тип данных. Реальный backfill вызывает OpenAI: в локальной среде с региональным 403 его не запускать. После разрешённого запуска сначала небольшой limit, затем повторный inventory/coverage. Публикация каждого вектора условна по исходной версии; цена ошибки — повторное вычисление, а не замена нового источника старым.

Старые цены без времени наблюдения не получают выдуманное «сейчас». Их проверяет обычное чтение цены сайта. Для ремонта конкретных старых price facts сначала выбрать проверенные UUID и сохранить снимок строк; в транзакции выполнить `UPDATE products SET price=price WHERE id=ANY($1::uuid[])` с явным списком UUID. Trigger пересоберёт только их price mirror, не обновляя дату доказательства. Проверить readback и commit. Не запускать это как безусловный UPDATE всего каталога.

Для ошибочного источника отзывать только конкретные строки `verified_product_facts` по subject/attribute/source URL, сохраняя snapshot и причину. Не удалять все знания. Новое независимое подтверждение допускается; отклонённый источник не возвращается обычной enrichment job. Неполный crawl не является разрешением массово деактивировать товары.

## Проверки

`npm run verify` — typecheck, unit, build, dependency audit, offline oracle и его mutations. Это не семантическая приёмка.

I-тесты `tests/*.integration.mjs` требуют явную отдельную loopback БД с именем `bakaut_acceptance_*`, pgvector и миграциями. Запуск: `node --import tsx tests/<name>.integration.mjs`. Не указывать рабочую DATABASE_URL. Для тестов очереди использовать чистую БД: некоторые старые suites сохраняют fixtures. `leadHttpSinkLifecycle` запускает настоящий worker и локальный HTTP-приёмник без писем сотрудникам.

`node evals/acceptance/production-mutations.mjs <output-dir>` временно ломает реальные владельцы выполнения на изолированной БД, проверяет assertion failure и восстановленный контроль; наконец восстанавливает файлы/trigger. Не запускать параллельно с редактированием, проверкой или сборкой исходников.

`node evals/acceptance/plan-evidence.cjs <plan.json> <evidence.json>` проверяет case/variant/level, setup, fingerprint, receipt reuse и SHA256 raw artifacts. Непроведённые S/L остаются NOT_RUN. Один production-диалог не удостоверяет исходный широкий V4 S/L-пакет.

## Выпуск и восстановление

Commit/push/merge GitHub → автоматический Railway deploy → `/api/ready` 200 → совпадение commit/runtime/frontend/config → реальный виджет. `/api/health` показывает живой процесс, а `/api/ready` проверяет БД, физическую схему, price triggers и локальную конфигурацию без платных внешних probes. Admin health раскрывает backlog и degradation отдельно; ready не доказывает доставку письма или доступность OpenAI.

При остановке приложение прекращает таймеры и новые claims, дожидается текущих фоновых операций. Не завершённые jobs остаются durable и восстанавливаются с новым lease. Ответ провайдера с неизвестным результатом не даёт права выдумывать успешную доставку.

Суточный резерв OpenAI удерживается на всё 24-часовое окно, если исход вызова неизвестен или ответ не содержит usage. Сетевой сбой и отсутствие usage не освобождают резерв как нулевую стоимость. Подтверждённый usage переводит резерв в фактический расход; явное освобождение допустимо для достоверно не отправленного вызова. Это консервативное ограничение расходов, а не оценка счёта провайдера.

Откат выполняется revert через GitHub; additive schema оставляется. Перед откатом к старому коду оценить уже существующие NULL-имена, новые page jobs и цену: предпочтителен небольшой roll-forward. Не удалять миграции и не переводить отправленный outbox в pending ради повторной отправки. После восстановления повторить ready, marker, backlog и целевую проверку; ручной Railway upload не нужен.
