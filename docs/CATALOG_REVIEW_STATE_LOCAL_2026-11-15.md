# Сохранение оценок товаров между шагами исследования

Бот должен самостоятельно выбирать источники и пересматривать пригодность товаров. Этот локальный этап убирает необходимость заново выдавать весь список оценок после каждого поиска. Исходная версия кода: `8882779e425284c3a473d14e94d840af73789203`. Ветка: `perf/catalog-review-state-local-20261115`.

Результат сохранён локально. Платные API не вызывались, PostgreSQL не устанавливался и не запускался. Публикации, push, PR и изменений каталога в этом этапе нет. Живая приёмка нового поведения не проводилась. Предыдущая приёмка v12 не подтверждает эти изменения.

## Что изменено

После первой полной оценки сохраняется запись каждого кандидата: ID, точное название, решение модели, основание, ответ модели и доступные в тот момент внешние источники. Состояние связано с вопросом, историей, ранее показанными товарами, версией каталога и полными переданными карточками. Порядок кандидатов хранится отдельным массивом, поэтому перестановка ключей JSON в хранилище не меняет выдачу.

Следующий совместимый шаг получает все оригиналы, прежние оценки и результаты поиска. Модель возвращает только выбранные ею изменения. Она может пересмотреть любой ID, включая ранее принятые и отклонённые товары, либо сохранить все оценки. Код проверяет целостность, ID, точные названия, наличие оснований и привязку к прежнему состоянию. Пригодность товаров код не определяет.

Новый источник допускает пересмотр любой оценки. Если прежний источник потерян или изменён, изменились условия, история, карточки или снимок каталога, следующая оценка строится полностью. Сохранённое продолжение с изменённым контекстом отвергается до повторной отправки. Повреждённое состояние не используется как основание ответа.

Каждая оценка сохраняется отдельной контрольной точкой по ID ответа модели. Окончательное состояние входит в метаданные ответа. Известный ответ при восстановлении читается повторно. Отправка с неизвестным результатом не повторяется автоматически. Старые сохранённые планы без нового формата поддерживаются.

Применён принцип Model the Domain: единое состояние оценок содержит данные и их происхождение, вместо разрозненных флагов в поисковых шагах.

## Повтор сохранённого аудита

Использована сохранённая начальная оценка 132 генераторов и ожидаемый список из 34 ID из предыдущего аудита. Обновления для 060048 и 060038 заданы в тесте по прежнему результату проверки. Ответы новых поисков заменены тестовыми данными. Это проверка переноса решений, а не новая оценка качества модели.

Результат содержит ровно 34 ожидаемых ID. Потерянных и лишних ID нет, основания сохранены для всех 132 кандидатов. На двух последующих шагах выданы две изменённые оценки вместо повторной выдачи 264 записей.

Размер только JSON с решениями в полном формате составил 39 022 и 38 824 байта UTF-8. Массивы изменений составили 330 и 313 байт. В эти числа не входят входной контекст, сохранённое состояние, оценка источников, текст ответа, токены провайдера и время работы. Полные оригиналы по-прежнему передаются модели. Ускорение и снижение общей стоимости production не измерены.
