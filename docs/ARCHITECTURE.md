# Architecture

## Компоненты

- `src/server.ts` запускает Fastify.
- `src/app.ts` собирает API, CORS, rate limit, healthcheck и маршруты.
- `src/ai/*` содержит GPT-5.4 оркестратор, промпты, извлечение потребностей и embeddings.
- `src/catalog/*` содержит crawler сайта, CSV-импорт и нормализацию.
- `src/db/*` содержит подключение к PostgreSQL, миграции и репозитории.
- `src/client/*` содержит React iframe-виджет.

## Поток сообщения

1. Виджет создает `conversation_session`.
2. Покупатель отправляет сообщение в `POST /api/chat/sessions/:id/messages`.
3. Backend сохраняет user message.
4. AI-слой обновляет `CustomerNeedState`: явные потребности, скрытые выводы, ограничения, критерии, конфликты.
5. Backend ищет товары в PostgreSQL full-text и pgvector.
6. Если данных мало или есть конфликт, GPT-5.4 получает web search tool.
7. Ассистент генерирует ответ, backend стримит SSE в виджет.
8. Assistant message, карточки и metadata сохраняются в БД.

## Память сессии

Сессия активна до закрытия вкладки. Виджет отправляет heartbeat и `sendBeacon` на close. Если close не пришел, сервер закрывает сессию после 30 минут неактивности.

## Почему не жесткие сценарии

Проект хранит структурированное состояние потребности и передает его GPT-5.4, но не выбирает ответы через жесткое дерево условий. Кодовые условия используются для маршрутизации данных, safety-ограничений и надежности, а не для имитации менеджера.
