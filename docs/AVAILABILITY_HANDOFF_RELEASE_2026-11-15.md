# Полный вопрос и товары в заявке

Покупателю нужен полезный ответ и точная передача его запроса менеджеру. Пакет сохраняет полный вопрос и проверенные IDs товаров через чат, форму, outbox и новый snapshot письма. Общий текст вроде «уточнить эти две модели» больше не теряет структурный список товаров.

Форма использует сохранённую серверную область заявки. Клиент не может подменить IDs. Новые решения агента с неизвестными товарами или некорректной структурой явно отклоняются. Предварительно сохранённое продолжение заявки сохраняет свою область. Семантическое решение и выбор источников остаются у агента.

Общий предел вопроса составляет 3000 Unicode code points. История и форма принимают ту же строку без обрезания середины суррогатной пары. В письмо передаётся полный вопрос, а ниже отдельный читаемый список IDs каталога. Названия и ссылки не выдумываются. Метаданные snapshot не добавляют полей в запрос Resend.

При повторной отправке используются прежние body и idempotency key. Сохранённый snapshot не пересобирается по изменённому текущему контексту. Старые заявки и snapshots без IDs не дополняются задним числом. Миграции таблиц нет.

Локально прошли 2079 тестов, один PostgreSQL тест пропущен. Typecheck, build и no-regex прошли. Дополнены проверки оркестрации большого списка каталога и учёта usage перед checkpoint. Тест цепочки capture, repository, outbox и письма запускает реальные функции с SQL mock и fake HTTP. Он не доказывает выполнение PostgreSQL JSONB, реальную доставку письма или качество всех ответов агента. Результат CI и реальной проверки виджета записывается в протокол публикации.
